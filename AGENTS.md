# AGENTS.md

## Planning
- First read the skills, instructions, existing file/code structure and then decide how to solve the problem. Then come up with a plan. If the plan is non obvious or convoluted or some parts are contradictory, then ask me about it.
- The code structure you plan should be modular with clean and testable interfaces. You should be ready to split code into smaller parts/modules/files as it starts becoming bigger instead of putting everything in 1 file. 
- While planning UI changes look into ShadCN and Assistant-UI skills and components to figure out the best approach.


## Coding standards
- Always apply and adhere latest react19 and typescript clean code standards.
- Always follow mudit-style-guide skill for updated style guide written by project owner mudit. When it violates another skill, point out the inconsistency.
- Consult the skills so that you're following clean, simple, modern design and coding standards for react, assistant-ui, shadcn and nextjs.

## Offline Test 
- Always add playright test for UI functionality change.
- Run existing tests to confirm they pass.

## Build
- Always build with npm run dev and check the output log log.txt file for any new errors. 
- Fix those errors before proceeding.

### Log Location
Output location is available at log.txt. To verify the result of changes and read outputs, read log.txt
Generated by modifying package.json
"scripts": {
    "dev": "next dev 2>&1 | tee log.txt ",
    ...
  },

## Runtime Test 
- Always test with agent browser to see if basic and newly added functionality renders properly

## Code submit 
- If not asked by user in prompt, then never commit to git without asking. Only allowed to commit without asking for trivial changes.
